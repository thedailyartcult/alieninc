The Memory Layer

CMB stores durable facts, recalls them under a hard token budget, and hands context from one session to the next — so your AI starts where it left off, instead of re-reading everything from scratch.

Every significant decision, architecture choice, and bug fix becomes a recalled memory. Agents no longer waste tokens re-reading context they already have.

The result is a persistent memory layer that turns each AI session from a blank slate into a continuation — with full bi-temporal history so every correction keeps its audit trail.

Core Capabilities

/01 Token-Budgeted Recall

Hard Budget Enforcement

Ask for "512 tokens about the nginx config" and get exactly that — a packed context window with hard budget enforcement, not a file dump. Hybrid vector + lexical retrieval finds the memory you mean.

/02 Session Handoff

Cross-Session Continuity

End a session with a compact summary and open threads. The next session starts with that context injected — no 450K-token transcript resume. An interrupted task picks up mid-flight.

/03 Bi-Temporal History

Every Correction Preserved

Every correction keeps its history. Ask "what did we believe three months ago?" and CMB shows every version of a fact, when it was true, and what replaced it. Nothing is ever deleted.

/04 Governance & Audit

Hash-Chained Receipts

Hash-chained operation receipts, bi-temporal corrections, pinning, and scoped visibility (session → repo → workspace) keep memory trustworthy. No data leaves the box.

CMB turns each AI session from a blank slate into a continuation. The past is no longer opaque.

How CMB Works

/01

Store Durable Facts

When an agent learns something — a file structure, an architecture decision, a bug fix — it stores it as a durable memory via the MCP protocol. Facts are scoped by workspace and repo.

/02

Recall Under Budget

Before reading any file, the agent recalls relevant memories under a hard token budget (e.g., 512 tokens). Hybrid vector + lexical retrieval finds the right memory — not just keyword matches.

/03

Handoff & Continue

When a session ends, a compact summary and open threads are stored. The next session starts with that context injected — zero context loss, zero re-reading. The agent picks up mid-flight.
