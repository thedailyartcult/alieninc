Integrating CMB into an AI Tool

CMB speaks MCP over stdio, so any MCP-capable tool (opencode, Claude Code, Cursor, and others) can use it. There are three layers of integration, from zero-effort to maximal savings.

1 · MCP Server (required)

Point the tool's MCP config at the wrapper. The wrapper renames every tool to cmb_* and bridges the environment:

# opencode.jsonc / .cursor/mcp.json etc.
"mcp": {
  "cmb": {
    "type": "local",
    "command": ["/srv/cmb/venv/bin/cmb-mcp"],
    "enabled": true
  }
}

The wrapper inherits CMB_DB_PATH and CMB_API_TOKEN from the environment. Nothing is written into the config file.

2 · Protocol File (recommended)

Add the token-saving protocol to the tool's global instructions so every session enforces recall-before-read discipline:

# AGENTS.md
## CMB Token-Saving Protocol (MANDATORY)
1. Before reading any file, cmb_recall_context(query, token_budget=512) first
2. Store durable facts after reading large files (>100 lines)
3. Use cmb_recall_context, not re-reads, for known files
4. End sessions with cmb_end_session (summary + open_threads)
5. If CMB already has the answer, USE IT — don't re-read the source

3 · Plugin (maximum savings)

For opencode, the cmb-resume plugin enforces the protocol automatically:

  • Injects the protocol into the system prompt.
  • Intercepts tool.execute.before — checks CMB before file reads.
  • Auto-stores large tool outputs (tool.execute.after).
  • Injects last-session context at startup.

location /panteon/cmb/        { root /home/alieninc/panteon; }

Verification

# 1. Engine is up
systemctl status cmb-engine
# 2. MCP tools are visible (tool list should contain cmb_start_session, …)
# 3. Round-trip a fact
cmb_remember(content="Integration smoke test", workspace="alieninc")
cmb_recall(query="integration smoke test", workspace="alieninc")
# 4. Savings report
cmb_context_savings(workspace="alieninc")
Restart the AI tool after any config/plugin change so the new MCP process and plugin load.
