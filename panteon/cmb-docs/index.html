Overview & Quickstart

CMB — Persistent Memory for AI Agents

CMB (Cosmic Microwave Background) is Alien Inc's self-hosted memory layer for AI agents. It exposes 31 cmb_* Model Context Protocol (MCP) tools that let any agent store durable facts, recall them under a hard token budget, and hand context across sessions — eliminating the waste of re-reading the same files and transcripts every time.

Owned by Alien Inc. CMB is 100% Alien Inc property. Fully self-hosted on alieninc.tech, no third-party dependencies, no data leaves the box.

Quickstart

  1. Connect any MCP-capable AI tool to /srv/cmb/venv/bin/cmb-mcp.
  2. Configure the two environment variables: CMB_DB_PATH and CMB_API_TOKEN.
  3. Start a session: cmb_start_session with a workspace + repo + goal.
  4. Store a fact: cmb_remember — keep it a crisp, durable statement.
  5. Recall it later: cmb_recall_context with a token budget (e.g. 512).
cmb_start_session(workspace="alieninc", repo="backend", goal="Refactor auth")
cmb_remember(content="Auth uses HMAC-signed X-YONO-Signature headers",
             workspace="alieninc", repo="backend", title="Auth scheme")
cmb_recall_context(query="how is auth signed?", token_budget=512)

Core Concepts

  • Workspace → Repo → Session. Memory is scoped: facts live in a workspace (e.g. alieninc), optionally narrowed to a repo, and can be tied to a session.
  • Token budget. Every recall packs relevant memories into a hard context budget — "give me 512 tokens about X" instead of a file dump.
  • Bi-temporal history. Corrections supersede but never delete. Every version of a fact, its validity window, and what replaced it are queryable.
  • Session handoff. Ending a session with a summary + open threads means the next one starts already caught up.
  • Grounded answers. cmb_recall_grounded answers only from stored memory, with citations — or abstains when evidence is insufficient.
